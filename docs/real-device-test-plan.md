## Status and rules

Build 5 is the audited development build. Build 5 installation and launch succeeded on the paired physical iPhone; strict signature and Apple entitlement/profile checks passed. This does not verify authentication, permissions or movement. None of the physical walking/driving, Apple consent, Tesla or APNs cases below has been claimed as passed. Earlier build-3 installation is not evidence that build 5 or native Apple authentication works.

Keep the same Letm3go installation; **do not uninstall** to resolve login or plugin errors, because local encrypted journeys may be lost. Connect by a data-capable USB cable, unlock the phone and accept Trust if prompted. Record build/version from Profile → Diagnostics and keep it with every result. An unlocked phone is not proof that the USB tunnel is established.

Use these result labels: Automated pass / Simulator pass / Real-device pass / Live integration pass / Not tested / Failed. For physical tests record date, build, iOS version, permission state, battery before/after, app/lock state and approximate elapsed time. Report diagnostic counts/states rather than exact Home coordinates or token material. Never send Apple codes, Supabase tokens, Keychain dumps or private-key files.

A failed case is a failure, not a simulator pass. Missing History entries, a
duplicate activity for one stop, or a driving trip that absorbs a long on-foot
walk must all be reported with the Diagnostics snapshot.

For GPS: build/iOS, manual vs automatic, Always/Precise/Motion settings, native store status, active/detection state, recent fix time/accuracy, point/trip count, app lock/background/force-quit sequence, battery/elapsed time. Describe approximate movement instead of publishing exact Home coordinates. A map screenshot alone does not establish background recording.

For authentication: button pressed, cancellation vs error, whether native Apple sheet opened, exact non-secret error text, account suffix and Check sign-in outcome, restart/sign-out steps. The agent may then use read-only queries scoped to the supplied account suffix to verify Apple identity/profile/session metadata. No credentials or token values are needed.

For native bridge failures: record plugin/method name and build, confirm signed binary contains the custom registered controller; reinstall the verified build over the existing app. Do not wipe local data or fabricate web GPS as a fallback.

For cloud/Tesla/R2: operator-approved test account, endpoint/action, HTTP status, request timing and correlation ID if available; redact Authorization, signed media URLs, exact coordinates, OAuth codes/state, VIN/user email and object paths. A failed call must remain a failure, not substitute demo data.
