## Files and architecture

`website/public` contains the plain HTML/CSS landing page, existing route-arrow branding and a favicon. System fonts, responsive light/dark styling, no JavaScript, analytics, cookies, external fonts or runtime dependencies. Footer has only Letm3go branding; no invented email/legal entity.

`website/worker.js` serves the asset allowlist with CSP, HSTS, no-referrer and nosniff headers. HTTP and www redirect to HTTPS apex. Unknown paths return 404, never an app/SPA fallback. The public-key path is served directly as raw P-256 PEM; it returns 503 if missing/invalid, never a fake key or the homepage.

`website/wrangler.jsonc` isolates static assets from the app's `dist`. Wrangler is a pinned development dependency in the independent website package. It has no domain bindings until you deliberately add them. Worker observability and preview URLs are disabled; this does not disable Cloudflare's mandatory security/operational processing. Do not enable request-URL logging, Workers Logpush, tail sampling or analytics on the OAuth callback. Review account-level logging destinations and redact/exclude callback query strings there too.

`website/validate.mjs` blocks deployment unless the asset tree contains only allowed public files and the correct public P-256 key. It rejects symlinks/private-key signatures and known credential formats. The website asset directory must never contain environment files, iOS assets, project uploads or private keys.

## 1. Install your own Tesla public key

If an appropriate **Letm3go-owned** pair already exists elsewhere, keep the private key where it is and export only its public part. The matching private key will later be needed by the command/telemetry service; OAuth token exchange does not use it. Back it up securely and do not rotate it casually once paired with vehicles.

Otherwise generate locally outside the repository (do not run this over an existing private key):

```sh
cd /Users/juliuspollak/Projects/letm3go
(
  umask 077
  mkdir -p "$HOME/.config/letm3go/tesla"
  test ! -e "$HOME/.config/letm3go/tesla/private-key.pem" || exit 1
  openssl ecparam -name prime256v1 -genkey -noout \
    -out "$HOME/.config/letm3go/tesla/private-key.pem"
  chmod 600 "$HOME/.config/letm3go/tesla/private-key.pem"
)
openssl ec -in "$HOME/.config/letm3go/tesla/private-key.pem" -pubout \
  -out "$HOME/.config/letm3go/tesla/public-key.pem"
node website/install-public-key.mjs "$HOME/.config/letm3go/tesla/public-key.pem"
```

The installer validates prime256v1/secp256r1 and copies **only** the public key to `website/public/.well-known/appspecific/com.tesla.3p.public-key.pem`. This public file is deliberately publishable/committable. Never copy the private key there or into a `VITE_*` variable. No real key pair was generated by the agent.


If Cloudflare CLI authentication is missing, configure it locally using Cloudflare's CLI login or a least-privilege deployment API token for this account, outside this repository and without sending it to chat. This is separate from Supabase and App Store Connect credentials. The agent did not initiate login. The command uploads only `website/public` plus the small Worker; it does not deploy Supabase or modify iOS.

In Cloudflare Dashboard: **Workers & Pages → letm3go-public → Settings → Domains & Routes → Add → Custom Domain → `letm3go.au`**. Review any conflicting A/AAAA/CNAME before replacing it. Cloudflare Custom Domains manages the required DNS and certificate. Do not add guessed Sitebeat IPs or point the domain at Supabase. Then add `www.letm3go.au` to the same Worker if desired; the Worker canonicalises it to the apex.

Record existing DNS entries before changing them. Replace only conflicting apex/www website records. Preserve MX, TXT, SPF, DKIM, DMARC and unrelated subdomains. If existing routing/custom-domain bindings exist in the Dashboard, inspect them before assigning this Worker; the local review cannot see them.

**SSL/TLS:** wait until the custom-domain certificate is Active and publicly trusted. Use Full (strict) for any remaining proxied external origins, not Flexible; this Worker has no Sitebeat origin. Enable Always Use HTTPS for public non-callback traffic or retain the Worker's HTTPS redirect. Verify there is no redirect loop. HSTS is sent only by the deployed Worker; no preload was requested.

**Access/WAF:** no Cloudflare Access application or browser challenge may block the landing page, exact public-key URL or callback. Review custom rules/Bot Fight settings and narrowly exempt these routes from challenges if necessary, without disabling protection across unrelated applications. Exclude the key path from broad redirects, SPA catch-alls and URL rewriting; the apex HTTPS key must return 200 directly. Exclude callback query strings from optional logs. ## 4. Tesla callback and backend prerequisites

Register exactly:

- Allowed Origin URL: `https://letm3go.au`
- Allowed Redirect URI: `https://letm3go.au/auth/tesla/callback`
- Public key: `https://letm3go.au/.well-known/appspecific/com.tesla.3p.public-key.pem`

The website callback does **not** implement a competing OAuth/session manager. It validates callback shape and sends only code/state or cancellation to the fixed existing Supabase `tesla` function **server-to-server**. Browser cookies and authorization headers are not forwarded. No request URL/code/token is logged by this Worker. It returns only an allowlisted `au.jpollak.journey://tesla/connected?status=…` redirect. Errors are generic/no-store, never reflected parameters; a bare visit returns 400 with instructions to start in Garage, not a fake success. Production callback over HTTP or www is rejected rather than redirecting credentials.

The existing Edge Function performs hashed single-use expiring state validation, binds the exchange to the original authenticated Letm3go owner, checks pending deletion, exchanges at Tesla's server endpoint, encrypts tokens and returns the existing native callback. **No mobile or Edge Function implementation was changed.**

Before real OAuth, separately approve/configure/deploy the existing `tesla` Edge Function and shared modules. Set server-only `TESLA_CLIENT_ID`, `TESLA_CLIENT_SECRET`, `TESLA_REDIRECT_URI=https://letm3go.au/auth/tesla/callback`, the correct regional `TESLA_FLEET_AUDIENCE`, and dedicated 32-byte base64 `ACCOUNT_CREDENTIAL_KEY`. Deploy with the repository config's `verify_jwt=false`: callback GET must be public; POST actions still authenticate internally. Check its private lease/state/credentials tables and grants without replaying the six manually applied migrations. `TESLA_API_READS_APPROVED` remains off until billing approval. Do not copy these secrets into the website or app. Existing code supports this redirect without an app rebuild, but changing its hosted secret/function needs separate approval.

Use only required scopes: existing implementation asks `openid offline_access vehicle_device_data`, with `vehicle_location` only on explicit location consent. Do not request vehicle-command scopes for the landing page. After domain/key availability, complete Tesla application review and regional partner registration (official docs below). Public key hosting alone does not complete partner registration or implement telemetry/import. No Tesla API billing or partner registration was performed.

Privacy/Terms pages were not invented. This initial page has no forms or analytics. If Tesla's application form requires policy URLs, provide reviewed policies identifying the real operator/contact, the app's actual location/photo/Tesla processing, hosting and deletion limitations before claiming compliance. Do not link a fabricated or generic legal document. Account deletion/revocation setup remains a separate release prerequisite.
